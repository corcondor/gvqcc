# V110 / V111 の重み33の故障: 別の合法復号では説明できない

## 値の不一致

返された70語を (Y) とする。先頭35行・35列のHankel行列
(H_{ij}=Y_{i+j}) は GF(4096) で階数35だった。35点以下の
モーメントなら、この階数は点数以下なので、候補は正確に35点を必要とする。
連続モーメントに対するモニック次数35の漸化式は正則な (H) により一意。
その多項式を全4096元で評価すると根は **975, 2409 の2点**だけで、
35個の相異なる基礎体の根を持たない。従ってこの返り値は
**どの合法な重み35以下の誤り分布のシンドロームでもない**。
V110 Extendedの実回路から取り直した70語と、V110/V111の保存70語は一致した。

既知の消去多項式 (p=X^4+X^2+2890=(X^2+X+3519)^2) でフィルタし、
66語から33点・33個の値・入力の全70語を古典計算で再構成した。
係数から元の値を得る除数は (x p(x))。フィルタはこの失敗例を診断するために
選んだもので、一般の回路内セレクタや修復は未実装。

## 位相の不一致

V110 Extendedの実ファイルをKickMix 1.0.0で実行。測定の実行フラグと結果を追加の
古典ビットだけに記録しても、各マスクで元KMBと値・位相・作業線が一致した。
ゼロマスクと一ビットマスクを比較すると、同じシードでも実行フラグは
2,471,256ビット異なった。一方、両方で実行された測定の結果には不一致がなかった。

独立したビット並列再生で、双方で実行された結果を矛盾なく一つに合わせた。
同じ測定サイト別の結果列で双方の実行フラグ・最終値・位相を再現した。
よってこの540組では、観測された208ビットの位相の不一致は
「同じシードでも測定結果が揃わなかった」ことでは説明できない。
全33個の真の位置のうち試験マスクへの応答が非零だった位置・値は
2610:1233、501:2450。試した12個の台の外の位置では0:3227のみ非零。
番号は評価器のマスク位置。未試験位置や全測定分岐については主張しない。

回路・採点の修復ではない。値の復元と位相をそれぞれ検証する必要があり、
最初に壊れる物理演算は未特定。本番候補のゲート数やスコアは変更していない。

## 再現

KickMix 1.0.0、Python 3.12、公式DQI評価器。入力フィクスチャは既存の
`GVQCC_DQI_w33_423bit_witness.json`、V110 Extendedの `dqi.kmb` は
SHA-256 `8010980d566e6b16d255bfa7f00b37fb0d00c62978cd8bd3932b1981adc05841`。

```sh
g++ -O3 -std=c++20 paired_capture.cpp -o paired_capture
g++ -O3 -std=c++20 forced_check.cpp -o forced_check
./paired_capture dqi.kmb recorded.kmb > layout.txt
python paired_check.py GVQCC_DQI_w33_423bit_witness.json recorded.kmb dqi.kmb
./forced_check dqi.kmb
python locator_check.py GVQCC_DQI_w33_423bit_witness.json
```
