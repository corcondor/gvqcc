# DQI 42-CCX反復核の実コード監査（2026-11-20）

**目的:** 同一CCXペアの局所消去ではなく、過去の実装で何度も用いられた計算核を抽出し、最適化単位を特定する。

**入力:** 会話添付 `submission(8).zip` の `dqi.kmb`。このファイルのSHA-256は `80151bfc87d5c8ca858654e487f093aeb336790dd183f963126ecbee1054b7c2`。量子ビット890、命令59,293,427、無条件CCX 360,687。ここでの数値は**読み取り専用の静的命令検査**で、採点・新規提出・公式Simulatorの実行ではない。

## 1. 実測：4,053個の完全同型カーネル

先頭のGF(4096) 12bit×12bit乗算に対応する42-CCX区間を、CCXの制御/標的の反復関係で候補抽出。全1,293命令を走査し、命令種類および **CX/CCX全2,628個のオペランド**をwireの全単射置換で正規化して照合した。

| 項目 | 結果 |
|---|---:|
| 1個の核の長さ | 1,293命令 |
| 内訳 | 42 CCX＋1,251 CX |
| 使用するwire数 | 36 |
| 先頭核の命令位置（両端含む） | 19,344,108〜19,345,400 |
| CCX骨格と全ゲート接続の両方が一致する核 | **4,053** |
| 核同士のCCX重複 | **0** |
| 核内のCCX合計 | **170,226** |
| 全無条件CCXに占める核内の割合 | **47.1949%** |
| CCX列で連続する同型核ペア | **3,464** |

単なる「42ゲートが並んでいる」という一致ではない。全1,293ゲートの**配線グラフがwireの改名を除いて一致**した。だから、入口・出口の任意状態・位相・dirty targetに対する同値な代替カーネルを1つ証明できれば、適用可能なcallerの数を非常に大きく取れる。

ただし、同型であることと、全callerの入出力制約やHMR条件が同一であることは別。置換可否は各callerで確認する。

## 2. 隣接核は2種類の異なる最適化問題

3,464隣接ペアの間を調査した。

| 核と核の間の命令 | ペア数 | 扱うべき代数 |
|---|---:|---|
| **CXのみ** | **2,661** | 2核合成後の出力束をGF(2)の同一線形座標に移し、84積の多出力テンソルを共同再合成 |
| HMRあり | **478** | X基底測定に伴う相対位相・フィードフォワードを含むチャンネル同値性で再合成 |
| その他 | 325 | SWAP/条件境界等を個別に解析してから判断 |

CXのみのペアは、`A\cdot B` と `A\cdot C` などの関連入力を持つ可能性があり、単一GF乗算テンソルrank42への行き止まりを避ける入口となる。ただし同じ物理レジスタが使われていても、中身が同一とは限らない。**入力の線形式と出口の線形写像を同じフレームに展開**し、初めて共有rankを評価する。

HMRを挟むペアを古典的真理値表だけで消してはいけない。位相の非線形性と測定分岐を固定し、必要ならtrace相位カーネルとして別のアルゴリズムに作り替える。

## 3. 「同制御ペアが多いのに削除0」の実体

全CCXを抽出した列で、隣接し、物理的な制御wire2本が同じなのは **49,439組**。そのうち中間命令がCXだけのものは**48,337組**。しかし両制御の入口値をsymbolic GF(2)で持ち、途中CXで再計算したところ、**同じ論理積として再利用できる組は0**。制御の片側だけが同じ線形式となる例は876組だった。

同様に同じ物理targetの隣接CCXで100命令以内・間がCXのみのものは**82,998組**。最初のCCXの非線形寄与を独立な形式tokenとして追跡すると、**82,973組で次のCCXまでに他wireへも拡散**。拡散先の平均は約8.536本、中央値7本。残り25組は次のCCXの制御にも入るため、別途高次非線形依存がある。

**教訓:** 物理wireの同制御/同標的一致は論理積の重複と全く異なる。既存の`dqi_affine_ccx_scan.py`（別の古いe986回路で正規化して削減0）と整合する。局所スキャン0を大域最適と解釈せず、少なくとも42積/84積/測定位相境界を単位に抽象化する。

## 4. 28.5に向けた数字上のレバー

今回の4,053核に対して、各核を**正しく**1T縮約すれば静的4,053T、2Tなら8,106Tに対応する。Round48のローカル費用値を基準に、Q・反復係数・他課題を固定し、これらがすべて**期待実行Toffoli**の削減に直結すると仮定した**理想感度**では、2T/核でおおむね28.5342となる。これは回路完成でもKaggle実スコアでもない。修復費用・branch確率・測定・量子幅が変われば成立しない。

既存の28.319台のKaggle実提出値はユーザー確認済み。本監査はそれを否定/再分類するためのものではない。今回の添付は別のSHAのDQI枝なので、28.319/28.321/修復ドナーに適用する前に必ずSHA照合する。

## 5. 実装の次の一手（判定条件まで定義）

**A. 最優先:** `CX-only`で連続する42T+42Tの実例を10〜20件、隣接している演算から抽出する。36本ずつの入口・出口をsymbolic GF(2)で同時正規化し、双方の入出力テンソルと「片側入力が本当に同一か」を決定する。84積を72〜83積へ落とすため、単発pair-flipではなく、GF(2)/GF(4)/GF(8)の非対称テンソル因子、3点以上のrank交換、必要なら一時rank増を許すbeam/SAT探索を使用する。

**B. 並行:** HMR境界を含む478ペアでは、位相の双線形trace形に変形する。分母の逆元が同一範囲で既に利用可能なら、`Tr(n d^{-1})` はdual-basisでの二体位相になり、相対位相をCZ/CXだけで付与できる**可能性**がある。既存の逆元の生存区間・phase correctionと作業線復元を確認してから採否を決める。HMRはX基底測定＋リセットであり、通常のゼロ化とは違う。

**C. 採用条件:** 入口の全wireの任意状態に対するゲート同値（またはcallerに関して証明された到達可能部分空間での同値）、dirty target、scratch復元、X基底HMR後の位相、条件ビット、固定DQI反例9件、追加ゼロ/次数差3/二重ゼロ、default/notebook各102,400-shot、同一18ファイルとコスト/ハッシュを記録。正しくない安価な枝へ戻さない。

**今回の進捗:** 同型核4,053個と隣接ペア2,661/478/325を実測で特定。**新しいToffoli削減回路・28.5超え・公式Simulator PASSはまだ作成していない。**

## 6. 追加実装: ブロックを84積に結合する際の次数検査

一つ目の42T核の各CCX出力を独立の記号とし、間のCXをGF(2)のXORとして厳密伝播させ、次の42個のCCX制御線にこの記号が入り込むかを**全2,661組**検査した。

| CX-onlyの隣接ペア | 件数 |
|---|---:|
| 84個の積を、切断面入力に関する二次写像として共同表現できる | **2,651** |
| 後半CCX制御線が前半の積に依存する（一般には高次） | **10** |
| 高次側で影響を受けた後半CCX | **420**（10組×42個） |

二次と判定された2,651組は、**この切断面の890量子線を独立変数とする代数的な局所写像**についての判定である。元の復号アルゴリズムの値、測定位相、入口の到達可能性、最終回路の正しさまで認証したものではない。

次に、2,651組の84個の積すべてについて、入口の線形制御形式 \((u_i,v_i)\)、出口の線形方向 \(w_i\) を、前後のCXを含めて同じGF(2)座標に正規化した。

| 追加探索 | 結果 |
|---|---:|
| 84個の出口方向がすべて異なるペア | **2,606** |
| 84積が42種の出口方向に合流するペア | **45** |
| 同じ積と同じ出口方向を持つ完全重複 | **0** |
| 同じ出口方向・共有制御因子の2→1積変形 | **0** |
| 同じ論理積を異なる出口方向へ供給する再利用 | **0** |

**結論:** 2核の単純なペア削減も残っていない。次は二次テンソルの**3項以上を同時に動かすrank交換**、42積の両側を出力方向込みで変える非対称再合成、またはアルゴリズム到達空間での合法な制約を用いた別テンソル構成が必要。45組の「同一42方向へ2セットの42積を足す」形は、小規模テンソル研究に優先的に渡すが、42積へ縮むとは主張しない。

## 7. 機械的に重要な切断面の注意

42Tテンプレートが全命令一致していても、**先頭のCCXから最後のCCXまでの区間だけでは、完全なGF(4096)乗算マクロとは言えない**。最初の12+12入力線・12作業線の計36本を全て独立変数として記号実行し、CCXの出力を42個の形式積として追跡したところ、指定された入口値そのままへ戻るsource bitは最初の12本中10本、次の12本中0本。target側でも線形恒等を保つのは12本中5本だった。入力基底の変更と復元用CXがこの切断面の外に残っている。

したがって、**既存コードの1,293命令だけを「完成した42T乗算器」として置換することは不適切**。joint tensorの合成は、前後の基底変換・scratchの出口契約・HMR境界を取り込んだ窓で行う。tensor rankだけ減っても、undoと量子線の生存区間まで含めない限り削減とはみなさない。
