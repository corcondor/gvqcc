## 変更した内容

### 1. 可換な順序と再合成

V111の同一量子線上の厳しい依存順序を、X型同士・Z型同士の可換性まで使うグラフへ拡張した。古典ビットの読書き、スコープ、一般角回転の順序、厳密にゼロと証明した境界を保持する。

採用版ではHMR事象の順序も維持した。独立HMRを入れ替える実験も行ったが、有料費用を下げる成果とはしていない。

新しい順序で隣接した区間に、V111由来の局所再合成器を適用した。新規に採用した947区間（Chemistry748、InvSqrt199）は、別実装のBoolean ANF検査を通過した。各置換以外の命令も全て照合している。再利用した合成器を新しい数学的発見として数えない。

### 2. 私有測定結果と、途中でゼロになる公開線

InvSqrtでは、新順序の回路に既存の仮想線消去を再適用し、9区間で12命令を削減した。測定結果が次の上書きまで読まれないこと、区間入口が厳密にゼロであること、全局所入力と両測定結果で値・位相が同じことを、合成器から独立した検査器で確認した。

さらに、公開入力線を永続的に使用中と見なす制約を外し、**無条件HMR後に厳密にゼロとなった区間**も検索した。q11の1区間が新しく対象となり、6命令を2命令へ置き換えた。

変更前は、q11に \(q_{36}+q_{24}q_{17}\) を生成し、q16へ使ってから測定・位相補正していた。変更後は、

\[
q_{16}\leftarrow q_{16}+q_{17}q_{24}+q_{36}
\]

を直接実行する。CCXは1個のまま、q11の局所保持とHMRを除去した。これだけで全体の量子幅が下がるわけではない。

### 3. DQIの実際の2区間

DQIでは、一時積を保持せず、使用先へ直接加算する2個の可逆shearを、正確なV111へ結び直した。

| 親のnative命令区間（0始まり・半開） | 解放した局所一時線 | 正味命令削減 |
|---|---:|---:|
| [25,867,148, 25,867,202) | q67 | 12 |
| [28,389,811, 28,389,881) | q3 | 14 |

2区間とも局所的には14本から13本の量子線になる。全体には900Qの区間が残る。

測定を先行させるため、プログラム冒頭の厳密にゼロなq1で二つの独立HMR結果を生成し、新しい古典ビットへ保存した。元の測定先へは元区間に到達してから代入する。古典ビット数は691,866から691,868になる。HMRの数、有料ゲート、元の公開レジスタは変わらない。

全回路比較では乱数列の位置を同じにするのではなく、**同じ意味を持つ測定事象へ同じ乱数を対応させる**。新しい測定の並べ替えによる標本差を、費用改善と取り違えない。

## 保持値を移して戻す実接続

命令削減の採用版とは別に、ユーザーが求めた「どの値を別の線へ持たせ、いつ戻すか」を具体化した研究回路を生成した。

対象は親V111のnative区間 [5590,5601)。この区間では、q26に保持されている任意の値 \(f\) を、次のように扱う。

| 段階 | 値の所在と操作 |
|---|---|
| 入口 | q26にf、q36は厳密に0 |
| 埋め込み | q26からq10・q11・q21へCNOTし、fをそれらの保持表現へ含める |
| 作業 | 元のq36の仕事をq26で行う。元のCXによって再使用線上の余分なfが相殺される |
| 元のHMR | q26を測定・リセットし、元と同じb281を得る |
| 復元 | 保存された関係式からfを1個のCCXとCNOTでq26へ再構成する |
| 表現を戻す | q26からq1・q10・q11・q21へCNOTして、全ての値を元の表現へ戻す |

復元式は、実際の出口の値で

\[
f=q_{10}+q_{11}+q_{21}+q_{35}
 +(q_{35}+q_{16})(q_{24}+q_{16})
\]

である。q36は置換した全27命令で一度も使用しない。追加の測定と一般角回転はない。

### 検証と費用

- 入口の関係式とq36=0は、22任意入力・333独立HMR結果を含めて普遍証明した。
- 合成器を使わない独立ANF引き戻しでも両方を証明した。
- 7自由局所入力×両測定結果、計256通りの全量子値・位相が一致した。
- 親と候補の保持27,898命令、メタデータ、区間前後を独立に照合した。
- 完全研究回路は全3,133,452合法入力・各1ショットで公式PASS。

ただし、この研究回路全体は**37Q**で、CCXが1個増える。親V111との同じ測定条件で、費用は60,865.34543887764から60,902.34543887764へ37増える。**局所36Qの接続の実証であり、費用改善版ではないため、採用した全18ファイルへ混ぜていない。**

研究回路は invsqrt/invsqrt_first_chart_connected.kmb、証跡は ordering/FIRST_CONNECTOR_INDEPENDENT.json と official/inv_first_chart_research/ にある。さらに隣接加算へ保持表現を渡す研究は invsqrt/ に記録する。

## 数学と探索の拡張

[MATH_JA.md](MATH_JA.md) に合成条件、証明、費用判定をまとめた。

特に実装したのは、次の3種類である。

1. **正確な非線形差分輸送。** CCXの二次差分項を含め、値と位相を一緒に更新する。物理線数ではなく線形式のランクで探索次元を制限する。
2. **零関係への情報の埋め込み。** 実際に成り立つ二次関係 \(r(y)=0\) と \(D_vr=1\) を使い、別の保持値fを \(y'=y+vf\) へ移す。複数ビット版は共通極化核とGF(2)右逆で探索する。
3. **将来の出力と位相を考慮した生成順序。** Chemistryでは、次の出力の制御値だけを優先せず、将来も必要になる独立積を早く生成して、測定位相に使える関係を増やす。

これらを実行した結果、有料ゲートの改善が確認できなかった探索範囲も保存した。上限内の失敗、固定した境界の下限証明、一般の未解決問題を混同しない。

### 同じ出口の二次復元を探し続けない根拠

InvSqrtの最初の主加算の出口（native5689の直後）では、q11とq36がゼロになる。残る35座標の次数2以下の特徴は、定数を含めて631個ある。合法入力から選んだ631点の正方minorがフルランクであることを、native再生と別実装の行消去で再確認した。

このため、この出口でゼロの2線を維持する**一定方向CNOT埋め込みと二次復元式**は存在しない。一般の36Q下限ではなく、出口・保持表現・復元次数を固定した否定結果である。三次関係592次元に対して、2,048方向と4,090個の関係を検査したが接続は未発見。全三次空間を網羅したとはしない。

次に変えるべき点は、キャリーが生きている段間へ復元境界を移すこと、または加算セル全体の非線形な保持表現を使うことである。詳細な独立証明と再現結果は invsqrt/README_JA.md にある。

### Chemistryの240 CCXは、まだ部分回路

将来必要な積を早く作り、位相消去に使える値と共有座標を組む方法を実builderへ接続した。構造の異なる15例すべてが、240 CCX・スピル0・再計算0で全95出力へ到達した。代表例は全1,219番地・任意35ビットの入力wordについて出力が一致し、過去63測定の位相係数も全て0である。

ただし、**82本の作業線が未消去**である。この native は `chemistry/UNFINISHED_PHASE_shared04/` に明記して保存し、完成18ファイルには含めていない。240 CCXの完成ローダーや費用改善としては数えない。

同じ15終端を後から直す方法のうち、条件付きCCZ合計2個以内、および1個のaddress-only CCXによる1座標置換後の二次位相消去は、固定した高位関数モデルで排除した。既存Bank0末尾の9・10・11 CCX窓にも、固定入口から1個減らせない独立検査可能な証明を残した。入口以前の関数生成や、複数の共有座標を変更する方法まで排除していない。

2本の将来方向を先に生成し、2本の共有座標を同時に選ぶ探索の条件とチェックポイントを chemistry/RESTART_PLAN.json に保存した。この2方向探索自体は今回実行していない。

## PR #178の確認

固定コミット 36d715e011a80e11bd1c4f6011163823bb5e2261 の資料と実装を取得した。

「24区間中1区間だけキャリーが起こる」という証明は、V61 B35の第一Horner接続の特定係数表に対するものである。24行×4096値を独立に再計算し、キャリーは係数行0の362値だけであることを再確認した。

この係数表の事実をV111の全加算へ一般化しない。V111の一般角回転33回を維持し、対応する到達範囲と保持表現を個別に調べる。V79完成36Q回路の7,747回転を、そのままV111へ持ち込む変更は行っていない。

取得内容と範囲証明は references/ にある。

## DQIの失敗原因について訂正を避けた点

過去の公開notebookにある13件の近似zero-test編集も確認した。しかしそれは、元 4b572141… から別版 b183c793… を作る編集である。現V111のV102由来provenanceは元 4b572141… を固定している。その13編集を、現在の既知失敗の原因とみなす根拠はない。

また、公開語S1のq3を解放できる切断点では、残る11本のS1線は実際に値を保持していた。途中の公開線集合が、そのまま元の単一GF語の意味を保つとは限らない。

現在不足しているのは、現nativeの内部物理値を、GF演算の段階・語へ対応させる意味写像である。有限体の漸化式で入力を正しく復元できたことだけから、最初の内部不具合を特定したとはしない。実測と系統確認は dqi/DQI_FOLLOWUP.json に記録した。

## 再現方法

Python 3、NumPy、C++17コンパイラを使用する。研究回路の公式検証やKMX関連にはKickMix 1.0.0、SMT証跡にはZ3を使った。実行環境は ENVIRONMENT.json にある。

既に展開した正確なV111から完全18ファイルを再生する：

~~~sh
python replay_all.py \
  --baseline /absolute/path/to/V111 \
  --out /absolute/path/to/new/V112 \
  --work /absolute/path/to/replay-work
~~~

--baseline へ元のV111 ZIPを指定することもできる。入力SHA、ゼロ境界、順序の依存関係、全保持命令、ANF、仮想線置換、DQIのリテラル置換、最終全SHAをチェックする。出力先は空のディレクトリを指定する。

公式検証を再実行する場合は、固定された公開verifierのcheckoutに対して：

~~~sh
python run_official.py --task chem \
  --candidate /absolute/path/to/V112/dfthcsos \
  --official /absolute/path/to/official \
  --out /absolute/path/to/new-chem-receipt

python run_official.py --task inv \
  --candidate /absolute/path/to/V112/invsqrt.kmb \
  --official /absolute/path/to/official \
  --out /absolute/path/to/new-inv-receipt
~~~

DQIの完全64入力比較を含む再生は dqi/replay.py にある。再生を探索の再試行と混同しない。探索に必要な依存資料・有限証明・状態チェックポイントは各研究ディレクトリに明記する。
