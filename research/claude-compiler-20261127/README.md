計算順序が得点（Toffoli・量子ビット）を変える場所を、実回路で調べました。命令数は公式得点に入りません。

## 結果

| 対象 | 試したこと | 結果 |
|---|---|---|
| 化学 | Antigravity の V75（PR #179 `a2f13006ab`, `family_3270_351710.zip`, k=5 が 231）を独立に検査 | **公式 verifier PASS**（既定 salt と新 salt）、247,763,620.91、405 Q。当方の 3,271 版と全アドレス往復で同じ語（`verification/`） |
| invsqrt (C1) | 条件分岐の内側へ Toffoli を移せるか（遅延評価） | **0 件**。1,507 個すべてを「抜いて比較」し、既知の古典ビット1個、または直近2個の OR で足りるものはなし |
| DQI | 同上（AND ガジェット 52,885 個の前向き解析、全 CCX 312,254 個の後向き可観測性解析） | **0 件** |
| DQI | 量子ビットを1本足して同じ積を保持する | 追加1本あたり最大 **38** 組。採算には約 710 組必要なので不採算 |
| 化学ローダー0 | 「保持値を測定して手放し、後で計算し直す」組み立て器（`loader/build3.py`） | 元の組み立て器が毎回失敗していた設定で完走し、**243 CCX**（128 Q、順逆とも全アドレス・全測定結果で一致）。現行の 242 にはあと 1 |

補足:
- invsqrt には、どの入力でも発火しない CCZ が4個あります（条件が常に偽の分岐の中）。もともと費用0なので、削っても得点は変わりません。
- 化学の全体幅は Q = (83+35) + max(287, 82) = 405 で、角度ローダーの一時領域は効きません。ローダーの順序が効くのは 128 本の上限の中だけです。

## 231 が失敗していた理由（当方の探索 25 件）

すべて「手放せるものがない: 必要次元 92 = 保持枠 92」で、不足はちょうど 1 次元でした。順序を貪欲に選び直すだけ（`loader/greedy_order.py`）では解けず、V75 のように**最初の約30積の集合の選び方**（残りの行との共有次元を小さくする）が効きます。`loader/minconn.py` はこれを入れ替え探索にしたものです（ローダー0で共有次元 61 → 58）。

## ファイル

- `analysis/pred_sink.py` / `pred_sink.cpp`: AND ガジェットの値が追加の条件下でしか読まれないかの解析（KMB をストリーム処理）。
- `analysis/obs_back.cpp`: 後向きの条件つき可観測性（部分的な死コード）解析。
- `analysis/sinktest.cpp`: Toffoli を1個抜いて、差が出るレーンが特定の古典ビットに含まれるかを調べる（invsqrt 用）。
- `analysis/deadcheck.cpp` / `opval.cpp`: 全 3,133,452 入力での削除可否と発火回数。
- `analysis/dqi_link_packing.py`: 追加量子ビットに保持できる同一積の組の数。
- `loader/build3.py`: 退避と再計算、条件つき CCZ による位相訂正を足した組み立て器。
- `loader/make0r.py`, `make0m.py`, `minconn.py`, `greedy_order.py`, `order_opt.py`: ローダー0の実行スクリプトと順序選び。
- `loader/` は先頭ローダーの組み立て器（`build.py`, `build2.py`, `frame.py`, `solve*.py`, `k8lib.py`）の上で動きます。それらはこのフォルダには含めていません。
