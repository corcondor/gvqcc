# 一般角回転とCCXの同時費用最適化

このディレクトリは、V79の**同じ位相関数**を使い、回転数とCCXの交換条件を最適化した実KMB、生成器、独立検証結果を収録する。31回転への移植とは別の、元の高回転系に対する改善である。

## 数学的な変換

Booleanなパリティ `s(x)` とフラグ `f(x)` に対して、整数として

\[
(s\oplus f)-s=f-2sf.
\]

元の回路は `a(s XOR f)` の回転を局所的に与え、同じ周波数の `-a s` を回路全体でまとめて補正する。右辺の表現を使えば、既にあるフラグ回転に `a` を加え、積 `sf` へ `-2a` の回転を与えられる。ある周波数の全出現を変換すると、その周波数に対する最後の補正回転を削除できる。

この変換は、係数を浮動小数で近似せず、2^128 を法とした整数角度として実装した。積を作る作業線が0なら1 CCXで計算し、HMRと条件付きCZで消去する。`patch_native.py` は全2^22入力の状態を実際に再生し、フラグの値と空き作業線の0をその場で完全に確認する。既存の部分空間スケジュールは保つ。原回路の回転線は `s XOR f` を持つため、前後にCXを置いて積の計算時だけ `s` に戻す。

## 探索

各周波数を変換するか否かを二値変数とし、必要になる新規フラグ回転も別の二値変数で持つ混合整数線形計画を解いた。一般角回転の費用を1回あたり約8.28 CCX相当として評価し、必要に応じて追加CCX予算を16、30、36に制限した。

ソルバーのgap=0は、この固定された周波数選択問題の線形化した目的関数に対する最適性である。全可逆回路の大域最適性や、厳密な非線形費用関数の全構造に対する最適性を意味しない。採否は出力KMBの実際のCCX数、命令数、一般角回転数、同じ最小精度余裕から計算する費用で判断した。

## 実測結果

|回路|Q|CCX|一般角回転|命令|独立費用式|
|---|---:|---:|---:|---:|---:|
|V79 tree36|36|1,267|7,747|53,942|2,298,148.075981|
|交換基底のみ exchange36|36|1,230|7,747|51,582|2,296,816.075981|
|exchange36_b16|36|1,246|7,731|51,646|2,292,623.659363|
|exchange36_b30|36|1,259|7,722|51,702|2,290,409.530792|
|exchange36_b36|36|1,265|7,719|51,729|2,289,731.504880|
|exchange36_b100000（費用優先）|36|1,590|7,631|53,266|2,275,210.530424|

これらはroot側の線形回路再合成を加える前の命令数である。最終採用回路はさらに命令数が少ない場合がある。

予算16/30/36の回路はV79に比べてCCX、回転、命令、費用がすべて減る。予算100000は実質的に追加CCX予算を制約しない費用優先案であり、CCXは増える。CCX最小案と混同しない。

全回路は、保存された `.receipt.json` の範囲で次の検証を受ける。

- 2^22個の全入力で、入力線と作業線が復元される。
- HMRごとに測定位相のBoolean係数を完全一致で検査する。
- 独立したC++ uint128位相計算で、元の目標位相と完全一致する。
- 全3,133,452個の合法入力で許容誤差を満たす。
- 最小余裕は元の位相と同じ138,112,178（2^-64 turns単位）。

ここにある独立検証は、公式KickMix実行やKaggle提出そのものではない。root側が実行した公式検証は、その実行記録を参照する。

## 再現

親ディレクトリ構造の `recovered/V79` と `synthesis` を保持して実行する。

```sh
python theory/rotcost/patch_native.py \
  --source synthesis/exchange36 \
  --stem theory/rotcost/exchange36_b36 \
  --budget 36
```

検証は `recovered/V79` を作業ディレクトリにして次を実行する。

```sh
python verify_echo.py ../../theory/rotcost/exchange36_b36 recip.plan.json
python cost.py ../../theory/rotcost/exchange36_b36
```

`select_and_emit.py` は新規にTreeMulti/SearchTreeから回路を生成する経路も提供する。最初の生成では部分空間探索を行うため、既存KMBへの直接パッチより遅い。`--budgets 16 30` は一度準備した基底計画を再利用して複数案を生成する。

## 31回転表現についての補題

今回の入力域は `1 <= x <= 3,133,452 < 2^22` である。真の `1/sqrt(x)` を34桁の二進固定小数に最近接丸めした関数は

\[
\left|\frac{\operatorname{round}(2^{34}/\sqrt{x})}{2^{34}}-
\frac1{\sqrt{x}}\right|\le2^{-35}
<\frac{2^{-24}}{\sqrt{x}}
\]

を満たす。第1・第2小数ビットの位相はClifford、第3ビットはT角、第4〜34ビットは31個の一般角回転で実現できる。これは31一般角回転の表現が可能であることを示す。

ただし、この34ビット関数を36Qかつ少数CCXで計算する方法は別途必要である。V79が既に使っている近似関数を34ビットへ丸めるだけでは、元の誤差と追加丸め誤差が重なり得る。上の補題は真の逆平方根を丸めた関数についての保証であり、V79近似の単純な丸めについての保証ではない。

## 実装上の区別

公式費用はT角とCCZ/CSWAPも数える。これらの回路は有料な非線形ゲートがCCXのみで、全回転が一般角なので、表の計算では追加のT角費用は0である。31回転仕様へ移す場合にはT角の費用を落とさず数える。
