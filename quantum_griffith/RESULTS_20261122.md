## 二つの学習方式を分ける

1. **LUT + learned wiring**: PyTorchのSTE / Gumbelで論理ゲートと配線を学習。ANF/アフィン教師の厳密回路から初期化できる。教師を超えた場合のみ新規な改善とみなす。
2. **Quantum-cost REINFORCE policy**: 入出力の可逆GF(2)基底CNOT変換を複数段サンプリングし、実際に合成した量子回路のCCX・作業線・CX・深さで報酬を計算。正しい関数のまま異なる回路表現を探索する。NNが学習するのは**変換列の選択方策**であり、一般のユニタリQNNではない。

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 4入力・1出力 bilinear | 4 CCX | 1 | 1（教師と同じ、補助線2本） | **1** | 1 | 未実施 |

### 4入力3出力の詳しい資源量

- **ANF**: 45 CCX / 9 qubits / 49 depth
- **古典入力アフィン深さ2**: 16 CCX / 10 qubits / 26 depth
- **PyTorch方策（深さ3、200更新×16サンプル=3,200エピソード）**: 14 CCX / 10 qubits / 14 CX / 22 depth
- **同じ3,200サンプルの独立ランダム方策**: 15 CCX / 10 qubits / 14 CX / 22 depth
- **古典入力・出力共同ビーム探索（深さ3、ビーム幅32）**: 14 CCX / 10 qubits / 14 CX / 22 depth
- 最良方策の変換列: input (1→2), input (0→1), input (2→3)。ここで制御/標的番号は0始まり

**解釈**: PyTorch探索はこの1題・1シードの比較では等サンプル数のランダム方策より1 CCX少ない解を見つけた。一方、探索深さを揃えた古典ビーム探索と同じ解に到達している。NNが古典回路探索より一般に優れるとは主張できない。また、深さ3ビーム幅32の候補評価回数と方策勾配の3,200エピソードは同一ではない。

## 検証・限界

- `verify_oracle` により `|x>|y>|0>` の全基底入力に対する `|x>|y XOR f(x)>|0>` とancilla復元をチェック。扱うゲートがX/CX/CCXだけなので、この検証範囲では相対位相の問題もない
- 確率的学習で得られた候補を無条件に採用せず、最良候補を可逆量子回路へ合成して厳密検証する
- PyTorch 400ステップ×3再始動（bilinear）／300ステップ×3再始動（output-mix）の **LUT学習では教師のToffoli数を改善できなかった**
- 7T/CCXは単純なT資源推定であり、量子ハードウェア・Clifford+T最適化・Kaggle KickMixの費用ではない
- 対象は小規模な人工Boolean関数のみであり、幅制約、相対位相補正、DQI復号器や化学ANGLEローダー実測、Kaggle公式検証は未接続

## 再現コマンド

```bash
bash quantum_griffith/install-pytorch-cpu.sh
python -m unittest discover -s quantum_griffith/tests -v
python -m quantum_griffith --case affine-product --inputs 4 --train --train-steps 400 --train-gates 12 --train-restarts 3
python -m quantum_griffith --case output-mix --inputs 3 --joint --policy --policy-steps 160 --policy-batch 12 --policy-depth 2
python -m quantum_griffith --case random --inputs 4 --outputs 3 --seed 21 --policy --policy-steps 200 --policy-batch 16 --policy-depth 3
python -m quantum_griffith --case random --inputs 4 --outputs 3 --seed 21 --affine-depth 3 --beam 32 --joint
```
