# score19のDQIで逆元に使う作業レジスタを再利用

基準のDQIはscore19の `e4e110436080b8538f50511dc7064185e1708c2bd386ea0e36322d7791311355`。
Q889、費用359707293756.04297、ローカル総合27.32812350537394。
コンポーネントを二種類・三方式で縮小した。別のQ889区間が残るので、
総合採点用のKMBには適用していない。

| コンポーネント | 元のQ / 課金ゲート（静的） | 改良後のQ / 課金ゲート（静的） |
| --- | ---: | ---: |
| GF24 第三ピボット、旧norm領域を借用 | 889 / 1,260 | **877 / 1,440** |
| GF24 第三ピボット、Frobeniusでその場乗算 | 889 / 1,260 | 883 / 2,268 |
| GF12 2語で共有する除算、prefix | 61 / 149 | **49 / 216** |
| GF12 2語で共有する除算、位相補償を含む往復 | 61 / 334 | **49 / 473** |

GF24のQは生産チャートと同じ840入力、所有24量子ビットを含む。GF12のQは
部品の係数・二語36量子ビットと保存フラグ1本を含む。GF12往復の実行平均は
299.0 → 472.93課金ゲート（2種の固定シミュレーターseed）。
課金ゲートによる増分と引き換えに、局所ピークで12量子ビットを解放した。

## GF24 の生存区間を割る

(N) を元の二次拡大体norm、(B=N^{-1}) をその逆元、
(C=operatorname{Norm}_{GF(4096)/GF(64)}N) を保持中の子normとする。
零にはinv0を使う。(B) のtower座標を (L,R) とすると
(N=((L+R)C,RC))。元の回路は (N) と (B) を生かしたまま
別の12量子ビットへデータのスカラー倍を書き込む。

新しい版では (N) を先にHMRし、保持中の (B,C) から測定位相を補償する。
空いた12本を両方のスカラー倍で使い、各旧語の測定maskを保留する。
その後、(B,C) から (N) を30 CCXで一度復元し、更新後のデータと
掛け合わせて二つの旧語maskの位相を補償する。このphase productは
古典条件付きCZで実現し、課金ゲートの追加は無い。
(N) をもう一度HMRして補償した後、同じ領域6本を最後のスカラー位相にも
再利用する。親から借りた量子線は全てゼロで返す。

スカラーの零フラグと子normの位相インターフェースを保つ。別々の逆元往復テストを
幅73の元回路および幅61の新回路それぞれ8,192ショットで行い、値、
フラグ、スクラッチ、位相で相違は0。さらに全第三ピボットの部品では、
独立な体演算oracleと比較して6,144ショットで値を確認し、うち3,072
ショットの往復で挿入した線形・三次位相も一致した。
このチャートも従来どおり、有限出力の定義域で検証した。

別法は (D=operatorname{diag}(a,a^{-1})) を3本の非線形shearとSWAPで
作り、(F_x D F_x^{-1} F_y D^{-1} F_y^{-1}) を適用する。(F_x,F_y) は
一方の語の二乗写像。合成は両方の語を (a) 倍する。係数零のときも
元の二次拡大体の非退化normによりデータは零であり、そのまま保つ。
4,095個の非零係数に対する24個の基底ベクトルと零の1ケースで
独立に検算した。既存の測定補償では12本全てのピークを取り切れず、
また課金増分が大きい。

## GF12 では一度だけ置く係数を二度使う

2語の除算では係数を一時的にその場で逆元へ変換し、12量子ビットの
積領域を両語で共有する。その場で係数をもう一度反転して復元する。
最初の係数のHMR maskは復元後の係数で補償する。二度目のmaskは
逆元のtower座標に掛かるため、既存の開いた位相ABIでそのまま返せる。
各語の古い値は復元した係数と更新後の値の積なので、旧語maskの位相も
課金なしで補償できる。

往復では新しい逆元位相部分も係数をその場で一時的に反転する。
更新後の係数のnormとその逆元を順番に作り、6ビットの作業レジスタを
二度のnorm計算に再利用して、保持したmaskを正しい時点で消す。
元回路と新回路で、prefixの出力・保持された位相、往復の値・
補償済み位相を計32,768ショット検査した。
従来のclosingを使った混在版の追加確認も `native/paired.json` に収録。

## e4での位置と残るピーク

`bind_with_hmr.json` はscore19のe4で3つのGF12 prefixを全命令・全オペランド
照合した。GF24 chart二箇所は直前の6a版で同じ照合をしたうえ、
e4採用時の公式HMR置換4件を適用した全列が実際のe4と一致することを確認した。
GF12 closingの手元の独立fixtureは全体テープ内の同一命令列に束縛できなかった。

これらの置換範囲は、保守的に幅889となる約967万操作位置のうち16,393位置を
覆う。先頭・終端の外側に残る重要な区間は、例えば
`[18496027,18502248)` の99-CCX GF24 adjoint consumeである。
この関数には上のnormの冗長な親子レジスタが無く、独立の回路再合成が必要。
rank-one項の順序だけを変え、完了した出力と未消費の入力を別々の線形基底で
保持する方式には次の障壁がある。出力方向がまだ全空間を張っていないとき
それらを消す非零の双対線形形式を選ぶ。その成分に寄与する未処理項の右入力形式
が全域を張らないなら、非零入力 (y) が全てを消すことになる。しかし (y) が
非零であるとき (x\mapsto xy) は全単射で、非零の出力形式を全ての (x) で
消すことはできない。従って出力次元23に達した時点でも残り入力の次元は24。
共同符号化や係数で変わる座標をこの議論は制限しない。

## 再現

派生したGF24チャート初期実装は Syed Asad Ali、Opus、Astra の
Apache-2.0版と、gvqccの `outcome_dqi_chart_inverse_norm.py` に基づく。
`$GVQCC` はこのファイルと `score5_dqi_width_check.py` を提供する既存リポジトリ。
公開Syedソースのディレクトリは従来の相対配置を使う。

```sh
PYTHONPATH="$GVQCC" python check.py native
PYTHONPATH="$GVQCC" python check_chart.py > native/chart.json
PYTHONPATH="$GVQCC" python check_paired.py native/paired_closed.json
PYTHONPATH="$GVQCC" python bind.py "$DQI_E4" "$E4_INTERVALS" native binding.json \
  --pre-hmr "$DQI_6A" --hmr-patch "$E4_HMR_PATCH"
```
