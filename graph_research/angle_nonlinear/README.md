# ANGLE 出力積のグラフ縮約

現行 score11 の5語ローダーについて、出力への非線形積2,915個を17区間に分けた。
前回の3項・4項XOR列挙と同じ、最初の1,216有効アドレスで得た高低混合係数
行列を使う。今回の方法は選んだ低側平面への**商写像の核**を求めるため、
何項を合わせるかの上限を設けず、見つかった核の全結合を検査できる。

各既存積の混合行列を A_i とし、候補の2次元低側部分空間 U を取る。
高側の各行を F2^15/U に射影して列として連結すると、係数 e が
この線形写像の核に入る条件は「XOR_i e_i A_i の全行が U に属する」こと。
核の各要素は階数2以下で、共通特徴バンク内では混合積1個の候補になる。

平面候補は元の積に現れる低側方向同士の全ペア、低側行空間の和が
3次元以下または高側行空間が交わる積ペアの低側和空間内の全平面、
既存3/4項探索の候補が張る平面。探索は指定した平面の中で完全。
低側15次元空間にある全平面や、元の混合行列の線形包の外部を
網羅したわけではない。

得られた候補の支持集合を超辺として、元の積を頂点にした超グラフを作る。
区間ごとに元の混合行列は独立だった。どの連結成分でも各積の
出力方向が独立なら、その成分に必要な出力部分空間は頂点数次元。
従ってその成分だけに支持を持つ辞書要素で全出力を張るには、
頂点数個以上の積が必要になる。逆に依存方向があれば、出力線形包を
含む超平面内だけでより小さい積集合を張れるか検査する。

## 実測

- 17区間、2,915積。低側平面 244,179 件、核の基底 2,915 ベクトル。
- 異なる候補 4,108 個。元の積を除く支持数の内訳は
  2項694、3項340、4項131、5項26、6項2。前回の4項種からの閉包と同じ候補集合の規模。
- 全連結成分で出力方向が独立。今回の積辞書では削減0。
  新しいKMBや改善スコアは生成していない。
- 人工6サイクルを別に検査した。指定の商空間の核基底は
  支持マスク 1 と 62。5個の辺の結合を列挙上限なしで回収できた。

## 軽量化と正しさ

certified モードでは高側76行を32本の固定線形射影に縮めて核を求める。
元の核は小さい写像の核に必ず含まれる。小さい方の核基底を全て
元の76行で検算し、全部成立すれば包含の逆向きも証明できる。
不成立なら元行列で核を計算し直す。このため固定射影で未知の項を
落とすことはない。all モードは最初から76行を使う比較実装。実際の244,179平面では
再計算0件、双方の核出力がバイト一致した。同一環境の各1実行の
壁時計時間は29.727秒→26.609秒。詳細は comparison_receipt.json。

## 再現

既存の j6_angle_experiments/j5/export.py で実際の15回路から segments.bin と
segments.json を再生成する。既存アーカイブの triples.txt と quads.txt は低側
平面選択の種。GCC C++17 の x86-64 Linux と Python 3 を使用。

```sh
g++ -O3 -std=c++17 plane_contraction.cpp -o plane_contraction
./plane_contraction segments.bin certified triples.txt quads.txt > kernels.txt 2> counts.txt
python contract_graph.py --matrices segments.bin --segments segments.json \
  --kernels kernels.txt --counts counts.txt --known triples.txt quads.txt \
  --out result_certified.json
python cycle_fixture.py ./plane_contraction
```
